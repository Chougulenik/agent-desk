# Epic 1: Streaming Chat Foundation

## Completed Tasks
- **Task 1**: Create a FastAPI endpoint that yields Server-Sent Events (SSE).
- **Task 2**: Connect a base LLM client to stream tokens to the FastAPI endpoint as they are generated.

## API Structure

### 1. `POST /api/v1/chat/stream`
- **What it does**: This endpoint accepts a user message and streams back an AI response token-by-token in real-time utilizing Server-Sent Events (SSE).

#### Input Format (JSON)
- **Schema**: `ChatRequest` (defined in `app/schemas/chat.py`)
```json
{
  "message": "string"
}
```

#### Output Format (SSE stream)
- Returns an `EventSourceResponse` (via `sse-starlette`).
- Each chunk is yielded as a standard SSE text stream format where the `event` type is `text_delta` and `data` contains the generated text token.
```text
event: text_delta
data: Hello!
...
event: text_delta
data:  You
```

## Implementation Flow

1. **Request Intake**: 
   - A POST request is received at `/api/v1/chat/stream` containing the user's message inside the `ChatRequest` body.
   - The routing logic is handled by mapping the `chat.py` router to the main application in `app/main.py`.
   
2. **LLM Connection Simulation**:
   - The endpoint invokes an asynchronous generator function `stream_llm_tokens(prompt: str)` located in `app/services/llm_client.py`.
   - Currently, this function simulates real-time token generation by splitting a dummy string into words and utilizing `asyncio.sleep(0.1)` between yields to emulate inference and network latency.

3. **Event Stream Generation**:
   - Within the endpoint, an internal `event_generator()` function iterates over the tokens generated by `stream_llm_tokens`.
   - It continuously yields dictionaries mapped to the SSE specification (e.g., `{"event": "text_delta", "data": token}`).
   - It implements disconnection handling logic (`await request.is_disconnected()`) to safely abort the loop if the client closes the browser tab early.
   - The stream is finalized and piped to the client via `EventSourceResponse`.
